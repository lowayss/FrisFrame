# FrisFrame

촬영 전 카메라, 배우, 소품, 동선을 2D와 3D에서 함께 설계하는 브라우저 기반 프리비즈 도구입니다.

현재 개발 범위는 프로젝트, 스토리보드, 수동 블로킹, 키프레임, 3D 카메라 프리뷰, MCP 명령 연동과 검토 후 내보내기에 집중합니다. 외부 영상 분석, 자연어 모션 프롬프트 블록, 외부 3D 에셋 가져오기는 지원하지 않습니다.

## 실행

MP4 프리뷰 인코딩을 지원하는 로컬 서버로 실행합니다.

```bash
python3 server.py --port 8766
```

```text
http://127.0.0.1:8766/
```

업데이트 전후의 전체 안정성 검사는 한 명령으로 실행할 수 있습니다.

```bash
python3 quality_check.py
```

코드 책임, 프로젝트 형식과 Electron 연결 원칙은 [`MAINTENANCE.md`](MAINTENANCE.md)에 정리되어 있습니다.

## macOS 데스크톱 앱

Apple Silicon용 설치 이미지는 버전에 따라 `release/FrisFrame-0.4.0-arm64.dmg` 형태로 생성됩니다. DMG를 열고 FrisFrame을 Applications 폴더로 옮겨 실행합니다. 현재 빌드는 로컬 검증용 미서명 버전이며, 외부 배포 전에는 Apple Developer ID 서명과 notarization이 필요합니다.

기존 로컬 서버 프로젝트를 데스크톱 앱으로 처음 옮기고 패키지를 다시 만드는 명령은 다음과 같습니다.

```bash
npm install
npm run check
npm run desktop:migrate-data
npm run desktop:build
```

프로젝트와 자동 저장 데이터는 앱 파일 밖의 `~/Library/Application Support/FrisFrame/data/frisframe.db`에 보존됩니다. 앱을 교체하거나 업데이트해도 이 DB는 패키징 과정에서 덮어쓰지 않습니다. Three.js와 Lucide는 앱 안에서 오프라인으로 로드하며, MP4용 FFmpeg도 앱 런타임에 포함됩니다.

## 기본 작업 흐름

1. `시나리오·콘티`에 원문과 컷 설명을 입력해 씬·컷 구조를 미리 확인하고 적용합니다.
2. `스토리보드`에서 컷 순서, 액션, 대사, 연출 의도와 검토 상태를 정리합니다.
3. 컷의 `블로킹 열기`에서 배우, 소품, 카메라와 포커스 위치를 2D 또는 3D로 배치합니다.
4. 원하는 시간으로 이동한 뒤 `키프레임 추가`를 눌러 선택한 대상의 키를 만듭니다.
5. 3D 카메라 프레임과 스토리보드 대표 프레임으로 컷의 흐름을 확인합니다.
6. 카메라 패널에서 최대 4대의 카메라를 만들고 각 카메라의 구도·렌즈·키프레임을 독립적으로 설계합니다. `멀티캠 보기`에서 모든 카메라를 한 번에 비교하고 화면을 클릭해 편집 카메라를 바꿀 수 있습니다.

7. 현재 프레임 PNG, 시작·끝 프레임 ZIP, 촬영 자료 ZIP 또는 H.264 MP4 프리비즈 영상을 준비합니다.
8. 준비 창에서 `파일 저장`을 직접 눌러 저장합니다.

## 기능 구성

FrisFrame의 작업 경계는 다음 네 층으로 나뉩니다.

- `스토리보드`: 씬·컷·액션·대사·카메라 의도와 검토 상태를 관리합니다.
- `무대·공간`: 배우·소품·세트 더미를 배치하고, 미터 기준 크기·월드 위치·깊이층·카메라 관계를 확인합니다.
- `동작`: 사용자가 직접 만든 키프레임 또는 MCP가 작성한 구조화된 동작 키를 저장합니다. 위치·방향·높이·경로·전환·포즈를 키 사이에서 보간하며 자동 보행·달리기 동작은 만들지 않습니다.
- `검토·내보내기`: 2D·3D 프리뷰, 멀티캠, 연속성 점검, 촬영 자료 ZIP과 선택한 MP4 출력 구간을 처리합니다.

MCP 클라이언트가 자연어 요청을 해석할 수는 있지만, FrisFrame에 저장되는 것은 자연어 문장이 아니라 확정된 공간 명령과 동작 키프레임입니다.

2D 무대의 긴 변은 36m로, 이전 24m 기준보다 1.5배 넓습니다. 16:9 무대는 약 36×20.3m이며 100%에서 작업창에 맞춰 표시되고 최대 400%까지 확대됩니다. 확대 상태에서는 빈 무대를 좌클릭 드래그해 이동하며, 가운데 버튼 또는 `Space + 드래그`는 대상 위에서도 무대를 이동합니다.

새 작업은 배우 1명, 소품 0개, 15초, 키프레임 0개로 시작합니다. 카메라, 배우, 소품을 움직이거나 추가해도 키가 자동으로 생기지 않습니다. 키는 사용자가 `키프레임 추가`를 눌렀을 때만 생성됩니다. 키가 없는 대상은 전체 시간 동안 현재 위치에 고정됩니다.

2D 평면도의 동선은 파랑(카메라), 청록(배우), 황색(소품)으로 구분됩니다. 전역 범례 대신 현재 이동 구간 바로 옆에 스토리보드식 화살표와 짧은 지문을 표시합니다. 빈 원은 시작점, 밝은 점은 현재 재생 위치, 십자 표적은 다음 도착점입니다.

## 키프레임

- `대상`에서 카메라, 배우, 소품 또는 전체를 선택합니다.
- `키프레임 추가`는 현재 배치와 시간을 새 키로 저장합니다.
- `선택 키 갱신`은 선택된 키를 현재 배치와 시간으로 바꿉니다.
- 마지막 하나뿐인 키도 삭제할 수 있으며, 키가 없어진 대상은 고정 상태로 돌아갑니다.
- 점을 클릭해 선택하고, `Cmd/Ctrl+클릭`으로 추가 선택하거나 `Shift+클릭`으로 같은 트랙의 범위를 선택합니다.
- 선택한 점 하나를 드래그하면 선택된 키가 간격을 유지한 채 함께 이동합니다.
- 선택 키는 복사한 뒤 현재 시간에 붙여넣을 수 있으며, 같은 대상의 기존 키와 겹치지 않는 가장 가까운 프레임에 배치됩니다.
- 두 개 이상 선택하면 `선택 구간`과 `구간 맞춤`으로 시작점은 유지하면서 전체 타이밍을 늘이거나 줄일 수 있습니다.
- `스냅`은 프레임, 0.1초, 0.5초, 1초 또는 끄기 중에서 선택합니다.
- `부드럽게`, `일정 속도`, `직전 유지`, `즉시 전환`으로 키 사이 움직임을 정합니다.
- 배우 동선은 키프레임에 기록한 위치와 방향을 그대로 보간합니다. 포즈 키가 있으면 사용자가 지정한 두 포즈 사이만 보간하며 자동 보행은 만들지 않습니다.
- 자동 탑승 배우는 차량의 좌석 포즈를 유지합니다.
- 통합 타임라인과 대상별 타임라인을 전환할 수 있습니다.
- `카메라 높이 키`는 현재 시간의 카메라 키가 있으면 높이만 갱신하고, 없으면 새 카메라 키를 만듭니다.
- 센서 포맷은 풀프레임, Super 35, APS-C 또는 직접 입력을 지원하며 센서 폭이 2D 시야, 3D 카메라 프레임과 구도 분석의 실제 화각에 함께 반영됩니다.
- 조리개는 컷 전체의 촬영 메타데이터이고, 포커스 거리는 카메라 키에 저장됩니다. 서로 다른 포커스 거리의 카메라 키 두 개로 랙 포커스 타이밍을 설계할 수 있습니다.

## 잠금과 연속성

- 카메라는 위치, 회전, 렌즈, 높이를 각각 잠글 수 있습니다.
- 배우와 소품은 `대상 편집 잠금`으로 2D·3D 이동, 속성, 삭제와 키 편집을 함께 막습니다.
- 잠금은 재생 결과를 바꾸지 않으며 기존 키프레임은 그대로 재생됩니다.
- 이어지는 컷은 직전 컷의 마지막 보간 프레임을 시작 배치로 사용합니다.
- 스토리보드의 컷 점검에는 180도 연기축, 화면 진행 방향, 배우 누락, 큰 위치·방향 변화, 탑승 상태와 소품 외형 변화가 연속성 경고로 표시됩니다.
- 의도된 연속성 변화는 이유를 적어 예외 처리할 수 있습니다. 해당 배치가 다시 바뀌면 기존 예외는 자동으로 무효화되어 재검토됩니다.
- 미해결 확인 항목이 있는 컷은 `확정` 상태로 바꿀 수 없습니다.
- 각 컷은 A안·B안을 고정 슬롯에 저장하고 2D 프리뷰와 주요 정보 차이를 나란히 비교할 수 있습니다. 버전을 복원하면 컷과 뒤이어 확정된 컷이 `검토 필요` 상태로 돌아갑니다.

타임라인을 문지르거나 재생하고 내보내는 동작은 편집 데이터를 변경하지 않습니다. 화면에서 실제 편집을 시작하거나 키를 추가·갱신할 때만 현재 자세가 반영됩니다.

## 3D와 내보내기

- 3D 무대는 미터 기준으로 보정됩니다. 표준 성인 더미의 기준 높이는 1.78m이며, 더미 유형과 X/Y/Z 배율은 실제 인물 외곽 크기에 반영됩니다. 세트·소품 메시도 카탈로그의 폭·높이·깊이에 맞춰 자동 정렬되고 바닥 기준면에 접지됩니다.
- 카메라 프리뷰는 렌즈·센서·카메라 높이·피사체 높이를 같은 공간에서 계산합니다. 선택한 배우나 소품의 속성에는 현재 해석된 `실측 스케일`이 표시되며, 배경시트 `scene_manifest.json`과 Seedance 프롬프트에도 미터 기준과 물리 치수가 기록됩니다.
- 3D에서는 대상 위의 좌클릭과 `G` 이동·`R` 회전으로 대상을 편집합니다. 무대 바닥이나 빈 공간의 좌클릭 드래그와 가운데 버튼은 오빗, 우클릭 또는 `Shift + 가운데 버튼`은 화면 이동, `Ctrl + 가운데 버튼`과 휠은 줌으로 동작합니다.
- 배우 동선 재생은 키 사이 이동 거리와 시간으로 위치·방향을 보간합니다. 포즈 키가 있으면 키에 저장된 포즈 사이만 보간하고, 걷기·뛰기 팔다리 동작은 자동 생성하지 않습니다.
- 오른쪽 아래 카메라 프레임은 현재 렌즈와 카메라 높이로 보이는 실제 출력 구도입니다.
- 카메라 패널의 `카메라 추가`로 컷마다 최대 4대의 카메라를 둘 수 있습니다. 카메라 이름, 색상, 위치, 방향, 렌즈, 높이와 카메라 키는 카메라별로 보존됩니다.
- `멀티캠 보기`는 현재 시간의 모든 카메라를 1·2·4분할로 비교합니다. 분할 화면을 클릭하면 해당 카메라가 편집 대상으로 활성화됩니다. `멀티카메라 프리뷰` 저장 창에서는 전체 시트와 각 카메라 이미지 복사를 함께 제공합니다.
- `멀티캠 영상`은 같은 카메라 순서를 유지한 2·4분할 H.264 MP4를 프리뷰로 준비합니다. 영상도 자동 저장되지 않으며, 플레이어로 확인한 뒤 직접 저장합니다.
- 스토리보드에서 선택한 컷은 `이 컷 이미지`로 현재 대표 카메라 프레임을 복사하거나 저장할 수 있고, `이 컷 영상`으로 해당 컷만 H.264 MP4 프리뷰를 준비할 수 있습니다.
- FrisFrame 프리뷰는 센서에 따른 화각을 정확히 보여주되 조리개·포커스에 따른 심도 흐림은 합성하지 않습니다. 제작 정보와 Blender 출력에는 센서, 조리개와 포커스 키가 포함됩니다.
- 키프레임의 `지문`은 `오른쪽으로 이동`처럼 화면과 촬영 자료에 표시할 짧은 메모입니다. 동작을 해석하거나 생성하는 프롬프트가 아닙니다.
- `2D 블로킹 이미지`는 현재 재생 위치의 배치와 전체 동선, 키 번호, 방향 화살표, 현재 구간의 지문을 1920px PNG로 준비합니다. 3D 가이드 영상과 함께 별도의 공간 참고 이미지로 첨부할 수 있습니다.
- `현재 프레임`은 현재 재생 위치의 카메라 프레임을 PNG로 준비합니다.
- `배경시트 레퍼런스`는 샷 카메라와 무관한 세트 전체 정면·좌측·우측 3D 개요, 2D 평면도, 카메라·장면 구조 JSON, 전체 FrisFrame 상태와 사용 규칙 README를 하나의 ZIP으로 준비합니다. 배우·인물 더미는 자동 제외하고 세트 건축과 소품만 남깁니다. 별도 프롬프트를 입력하는 기능이 아니라, Codex가 이미지와 구조 데이터를 함께 읽어 현실적인 배경 이미지를 만들 수 있게 하는 제작 패키지입니다.
- `시작+끝`은 정확히 0초와 전체 길이 끝의 카메라 프레임 두 장을 ZIP으로 준비합니다.
- `촬영 자료 ZIP`은 전체 프로젝트 컷 리스트 CSV, 연속성·검토 보고서, 활성 카메라 계획, 카메라별 `multi_camera_plan.json`, 동선 키프레임 CSV, Blender 스크립트, 2D 동선도와 카메라 스토리보드를 묶습니다.
- `프리비즈 영상`은 타임라인의 `MP4 출력 구간` 시작·끝과 FPS에 맞춰 해당 프레임만 렌더링한 뒤 H.264 MP4로 준비합니다. `전체`를 누르면 전체 타임라인을 출력합니다.
- MP4 프레임은 순서대로 전송하고 FFmpeg 인코딩은 앱 전체에서 한 번에 하나만 실행합니다. 다른 창에서 시작한 영상 작업은 앞 작업이 끝난 뒤 이어서 처리됩니다.
- 프리비즈 영상과 카메라 프레임에는 화살표, 지문, 앵커, 렌즈와 카메라 정보 같은 화면 표식을 포함하지 않습니다.
- 촬영 자료 ZIP에는 MP4를 중복 포함하지 않습니다. 영상은 별도 프리뷰에서 확인하고 저장해 패키지 준비 시간과 용량을 줄입니다.

MP4 생성에는 로컬 서버와 FFmpeg가 필요하며, 준비에 실패하면 다른 형식으로 바꾸지 않고 오류를 표시합니다.

## 프로젝트와 스토리보드

- 처음 실행하거나 최근 프로젝트가 없을 때는 프로젝트 관리 화면에서 제목을 입력해 새 프로젝트를 만들거나 기존 프로젝트를 열어야 합니다.
- 새 프로젝트는 제목과 서버 저장이 완료된 뒤 편집 화면으로 열리며, 제목 없는 임시 프로젝트는 저장되지 않습니다.
- 상단 `프로젝트` 메뉴의 `프로젝트 저장`은 현재 작업을 서버의 `내 프로젝트`에 저장합니다. 한 번 저장한 프로젝트는 편집 후 자동 저장됩니다.
- 저장 전 브라우저가 닫히거나 연결이 끊겨도 프로젝트별 복구본을 남기며, 다음 실행에서 서버 저장본과 비교해 복구 여부를 안내합니다.
- 상단 `프로젝트` 메뉴의 `최근 저장본`은 현재 프로젝트의 이전 저장본을 최대 5개까지 보여주며, 현재 상태를 이력에 남긴 뒤 선택한 저장본으로 복원합니다.
- 다음 실행에서는 마지막으로 열었던 관리 프로젝트를 자동으로 이어서 엽니다.
- `프로젝트 관리`에서 최근 프로젝트 검색, 열기, 이름 변경, 복제, 휴지통 이동, 복원과 영구 삭제를 할 수 있습니다.
- 저장본은 서버 revision으로 충돌을 검사하며 다른 창의 변경을 조용히 덮어쓰지 않습니다.
- 삭제는 먼저 휴지통으로 이동하며 휴지통 안에서만 영구 삭제할 수 있습니다.
- JSON은 프로젝트 이동·보관을 위한 별도 백업이며 서버 저장 상태와 구분됩니다.
- 프로젝트는 여러 씬과 컷을 포함하며, 각 컷은 독립된 2D·3D 블로킹과 키프레임을 가집니다.
- 시나리오 헤딩과 `컷`, `액션`, `대사`, `카메라`, `렌즈`, `길이` 표기를 읽어 편집 가능한 초안을 만듭니다.
- 자동으로 찾기 어려운 씬 연결은 적용 전에 미리보기와 경고로 확인합니다.
- 컷 카드는 대표 카메라 프레임, 샷 크기, 렌즈, 길이, 키 개수와 `초안`, `블로킹 중`, `검토 필요`, `확정` 상태를 보여줍니다.
- 기존 단일 작업 JSON은 불러올 때 새 프로젝트의 첫 씬·첫 컷으로 변환됩니다.
- 프로젝트 JSON에는 실행 취소 기록이나 대표 프레임 이미지가 포함되지 않습니다.
- 시나리오·콘티 창을 닫아도 적용 전 입력은 현재 브라우저 세션에 임시로 유지됩니다.
- 씬·컷 추가, 삭제, 복제, 순서 변경과 구조 적용은 스토리보드 화면에서 실행 취소할 수 있습니다.
- 빈 시나리오와 빈 콘티는 기존 프로젝트 구조에 적용할 수 없습니다.
- 스토리보드는 항상 전체 시나리오의 모든 씬과 컷을 씬 순서대로 이어서 표시합니다.
- 왼쪽 씬 목록을 선택하면 전체 시나리오 화면 안에서 해당 씬으로 이동합니다.
- 전체 시나리오와 상태 필터를 기준으로 `4컷 2×2`, `6컷 3×2`, `12컷 4×3` 이미지 시트를 만들 수 있습니다.
- 시트가 한 장이면 PNG, 선택한 칸 수를 넘어 여러 장이면 PNG들을 ZIP으로 묶어 준비합니다.
- 이미지 시트도 저장 전 프리뷰를 거치며 자동으로 내려받지 않습니다.

## 작업 화면과 단축키

- 상단의 `스토리보드`, `2D`, `3D`에서 작업 화면을 바로 전환합니다.
- 상단 `도움말` 메뉴에는 기능별 상세 설명을 제공하는 `기능 매뉴얼`과 화면을 따라가는 `처음 사용 가이드`가 함께 있습니다. 매뉴얼은 `F1`로 열고 닫을 수 있습니다.
- `Cmd/Ctrl+1`, `Cmd/Ctrl+2`, `Cmd/Ctrl+3`은 각각 스토리보드, 2D, 3D를 엽니다.
- `Cmd/Ctrl+S`는 현재 프로젝트를 서버에 저장합니다.
- 블로킹 화면에서 `Space`는 재생·일시정지, `K`는 키프레임 추가, `Shift+K`는 선택 키 갱신입니다. 정지 버튼만 재생 위치를 0초로 되돌립니다.
- 타임라인을 선택한 상태에서 `Cmd/Ctrl+A`, `Cmd/Ctrl+C`, `Cmd/Ctrl+V`, `Delete`로 키 전체 선택, 복사, 붙여넣기, 삭제를 실행합니다.
- `[`와 `]`는 이전·다음 키를 선택하고, 스토리보드의 `Alt+←/→`는 선택 컷의 순서를 바꿉니다.
- 입력창을 편집하는 동안에는 캔버스와 타임라인 단축키가 실행되지 않습니다.

## 저장 정책

이미지, 영상, 시작·끝 프레임, 촬영 자료 ZIP과 JSON 백업은 자동으로 내려받지 않습니다. 내보내기 준비 창에서 파일명과 형식을 확인하고 `이 프리뷰로 저장`을 직접 눌러야 다운로드가 시작됩니다. 프로젝트 자동 저장은 서버 데이터베이스에만 기록되며 파일 다운로드를 발생시키지 않습니다. 코드로 발생시킨 자동 클릭은 무시됩니다.

## 외부 배포 보안

외부 주소로 서버를 열 때는 라이선스 인증이 필수입니다. 원본 라이선스 키는 해시로 저장되고 브라우저에는 임의 세션 토큰만 전달됩니다.
외부 배포는 HTTPS를 종료하고 `X-Forwarded-Proto: https`를 전달하는 리버스 프록시 뒤에서 실행해야 합니다. 아래의 pepper는 충분히 긴 임의 문자열로 만들고 서버와 라이선스 추가 명령에 동일하게 전달합니다.

```bash
ENABLE_LICENSE_CHECK=true \
FRISFRAME_REQUIRE_ORIGIN=true \
FRISFRAME_SECURE_COOKIES=true \
FRISFRAME_LICENSE_PEPPER='충분히-긴-임의-비밀값' \
python3 server.py --host 0.0.0.0 --port 8766
```

라이선스는 서버를 실행하기 전에 별도 데이터 경로에 추가합니다.

```bash
PREVIS_DB_PATH=/secure/path/frisframe.db \
FRISFRAME_LICENSE_PEPPER='서버와-같은-비밀값' \
python3 add_license.py --owner "사용자 이름"
```

서버는 앱에 필요한 정적 파일만 허용하며 DB, 서버 코드와 Git 내부 파일을 제공하지 않습니다. 공유 프로젝트는 소유자 세션 또는 링크의 별도 공유 토큰이 있어야 열립니다.

## Model Context Protocol (MCP) 연동

FrisFrame 저장소는 Claude Desktop, Codex, Cursor 같은 MCP 클라이언트가 프로젝트 데이터를 읽고 구조화된 장면·동작 명령을 적용할 수 있는 별도 표준 MCP 서버를 제공합니다. MCP 클라이언트가 자연어를 해석하지만, FrisFrame은 자연어 모션 문장을 저장하거나 실행하지 않습니다. 현재 macOS 앱 패키지에는 MCP 실행 파일이 포함되지 않으므로 저장소의 `mcp_server.py`를 직접 연결해야 합니다.

### MCP 서버 실행 및 테스트

별도의 외부 라이브러리 설치 없이 파이썬 표준 라이브러리(Stdio 채널)만을 이용하여 가볍고 안전하게 실행됩니다.

* **동작 검증 (스모크 테스트)**:
  ```bash
  python3 tests/mcp-server-smoke.py
  ```
* **제공하는 AI 도구(Tools)**:
  - `list_projects`: 데이터베이스 내 프로젝트 목록 나열
  - `get_project`: 특정 프로젝트 JSON 문서 로드
  - `create_project`: 신규 프리비즈 프로젝트 생성
  - `save_project`: 수정된 프로젝트 JSON 저장 및 백업 리비전 생성
  - `create_cut`: 지시어 분석 기반 카메라 자동 가배치를 포함하여 스토리보드 컷 추가
  - `update_camera_blocking`: 특정 컷의 3D 카메라 매개변수(위치, 높이, 각도, 화각) 미세 수정
  - `add_actor_to_cut`: 3D 프리비즈 씬에 신규 배우 추가
  - `apply_scene_commands`: 레퍼런스 이미지에서 추출한 공간 앵커와 더미·소품·카메라 명령을 현재 컷에 반영
  - `apply_motion_commands`: 시간별 위치·방향·높이·경로·전환·포즈 키프레임과 출력 구간을 현재 컷에 반영

`apply_scene_commands`는 이미지를 프롬프트로 바꾸거나 외형을 복사하는 기능이 아닙니다. Codex/Claude 같은 비전 호출자가 레퍼런스에서 확정한 구조 정보를 `spatial_guide`와 `add_dummy`, `update_dummy`, `remove_dummy`, `set_camera` 명령으로 보내면, FrisFrame이 현재 컷에 저장하고 덩어리 블로킹으로 표시합니다. `world_x_m/world_z_m`은 무대 중심 기준 월드 미터 좌표이고, `physical_dimensions_m`은 `width/height/depth` 실측 치수입니다. 이 값이 인물과 세트의 크기 비례, 위치, 거리감, 깊이 순서를 결정합니다.

`apply_motion_commands`는 동작의 정본입니다. `add_keyframe` 또는 `set_pose_key`에 `source_id`, `time`, 위치·방향·높이와 `pose_preset` 또는 `body_pose`를 넣고, `transition`과 `path_mode`로 키 사이의 움직임을 지정합니다. `pose_preset`은 `armsCrossed`, `sit`, `crouch`, `wave`, `point` 같은 기존 포즈 코어의 프리셋만 사용하며, 걷기·뛰기 사이클이나 임의의 팔다리 동작은 생성하지 않습니다. `set_duration`과 `set_export_range`로 타임라인 길이와 MP4 출력 구간도 함께 지정할 수 있습니다.

예를 들어 배우를 0초의 기본 자세에서 2.4초의 팔짱 자세로 이동시키려면 다음처럼 보냅니다.

```json
{
  "project_id": "abcd1234",
  "revision": 8,
  "scene_index": 0,
  "cut_index": 0,
  "operations": [
    {"op": "add_keyframe", "source_id": "person-a", "time": 0, "label": "시작", "pose_preset": "neutral"},
    {"op": "add_keyframe", "source_id": "person-a", "time": 2.4, "label": "팔짱", "pose_preset": "armsCrossed", "x": 0.52, "y": 0.44, "transition": "linear", "path_mode": "straight"},
    {"op": "set_export_range", "start": 0, "end": 2.4}
  ]
}
```

예를 들어 레퍼런스 이미지에서 다음처럼 구조 계획만 보내면 됩니다.

```json
{
  "project_id": "abcd1234",
  "revision": 3,
  "spatial_guide": {
    "source_name": "set-reference.jpg",
    "status": "applied",
    "anchors": [
      {
        "id": "back-wall",
        "label": "후면 벽",
        "kind": "set",
        "world_x_m": 0,
        "world_z_m": -3,
        "dimensions_m": {"width": 10.2, "height": 3.0, "depth": 0.18},
        "depth_layer": "background"
      },
      {
        "id": "person-a",
        "label": "인물 A",
        "kind": "actor",
        "world_x_m": -1.1,
        "world_z_m": 1.8,
        "dimensions_m": {"width": 0.54, "height": 1.78, "depth": 0.36},
        "depth_layer": "midground"
      }
    ],
    "depth_layers": [
      {"id": "background", "label": "배경", "order": 0, "distance_m": 3},
      {"id": "midground", "label": "중경", "order": 1, "distance_m": 1.8}
    ]
  },
  "operations": [
    {
      "op": "add_dummy",
      "id": "person-a",
      "type": "actor",

```

FrisFrame 안의 이미지 입력은 레퍼런스 썸네일을 보관하고, 실제 이미지 해석은 연결된 비전 호출자가 담당합니다. 따라서 “같은 모양”이 아니라 이미지에서 측정한 구조 앵커가 데이터로 남습니다.

```json
{
  "project_id": "abcd1234",
  "revision": 7,
  "scene_index": 0,
  "cut_index": 0,
  "operations": [
    {"op": "add_dummy", "id": "person-a", "type": "actor", "dummy_type": "child", "x": 0.28, "y": 0.44, "height": 0.2, "rotation": 35, "color": "#ff6262"},
    {"op": "add_dummy", "id": "table-a", "type": "prop", "asset_type": "dining-table", "x": 0.64, "y": 0.58, "rotation": 90, "color": "#65d66f"},
    {"op": "update_dummy", "id": "person-a", "x": 0.34, "scale_y": 1.1}
  ]
}
```

MCP 명령이 저장되면 열린 FrisFrame이 약 1.6초 안에 새 revision을 확인해 현재 장면을 자동으로 갱신합니다. 저장되지 않은 수동 편집이 있으면 덮어쓰지 않고 충돌 상태로 멈춥니다.

### Claude Desktop 연동 설정

`~/Library/Application Support/Claude/claude_desktop_config.json` 설정 파일의 `mcpServers` 항목에 아래 내용을 추가합니다.

```json
{
  "mcpServers": {
    "frisframe": {
      "command": "python3",
      "args": [
        "/Users/loways/Documents/AI_Studio/01_projects/film-studio/02_tools/stage-blocking-lab/mcp_server.py"
      ],
      "env": {
        "FRISFRAME_MCP_OWNER_LICENSE_HASH": "local"
      }
    }
  }
}
```

`PREVIS_DB_PATH`를 생략하면 MCP 서버가 먼저 macOS 앱의 `~/Library/Application Support/FrisFrame/data/frisframe.db`를 찾아 현재 데스크톱 앱과 같은 프로젝트를 사용합니다.

MCP는 지정한 소유자 범위의 `managed` 프로젝트만 읽고 수정합니다. 로컬 라이선스 검사를 끈 기본 실행은 `local`을 사용하며, 라이선스를 켠 서버에서는 해당 사용자의 소유자 해시를 명시해야 합니다. 모든 수정 도구는 `get_project`에서 받은 현재 `revision`을 요구하며, 값이 오래되면 덮어쓰지 않고 충돌로 중단합니다.
